# G-HAL — منصة إعادة تصميم سير العمل الوكيلية

تنفيذ برمجي للنواة المفاهيمية الموصوفة في وثيقة **«إعادة تصميم سير العمل —
المرجع الشامل لأفكار ومكونات المشروع»**.

المشروع **ليس** أداة لإضافة مساعد ذكي إلى خطوة موجودة، بل منصة تعيد تعريف
العملية نفسها: تبدأ من الواقع الفعلي لا من الوثائق الرسمية، تفصل القيمة عن
الحركة، تكشف الاختناقات والاستثناءات، تقترح عملية مستقبلية مبنية حول النتيجة
وقدرات الوكلاء، وتحافظ على الإنسان في القرارات التي تحتاج سياقاً أو مسؤولية
أو حماية.

## الدورة الحاكمة

```
Process Discovery → Process Analysis → Zero-Based Redesign
→ Agentic-Native Design → Human-Agent Allocation
→ Risk / Policy / Authorization → Simulation and Verification
→ Controlled Execution → Continuous Audit
→ Exception Intelligence → Process Memory → Process Evolution
```

| `ghal/attention.py` | Human Attention Router (9.4) | لا إغراق للإنسان: ثقة + مخاطر + جِدّة + قابلية تراجع |
| `ghal/simulation.py` | Process Simulation Engine (9.2) | محاكاة مونت كارلو لسيناريوهات ما قبل الإنتاج |

## التشغيل

لا تبعيات خارجية — مكتبة بايثون القياسية فقط (3.11+):

```bash
# العرض التجريبي الكامل: معالجة الفواتير ودعمها (القسم 11)
python demo/invoice_demo.py

# الاختبارات (18 اختباراً)
python tests/test_core.py        # أو: python -m pytest tests/
```

## ماذا يعرض demo الفواتير؟

1. **اكتشاف**: بناء خريطة As-Is من 60 حالة فعلية (53.5 ساعة زمن دورة،
   احتكاك ~5000%، عنق زجاجة حقيقي في الموافقات).
2. **تحليل**: تصنيف الخطوات في الأرباع الأربعة وتقدير التوفير السنوي.
3. **إعادة تصميم من الصفر**: تفويض القواعد المتكررة للوكيل، إبقاء الحكم
   والدفع (غير القابل للعكس) بشرياً — مع مبرر موثّق لكل قرار.
4. **محاكاة**: مقارنة As-Is بثلاثة سيناريوهات To-Be قبل أي تنفيذ.
5. **تنفيذ مراقَب**: 4 حالات عبر Process Harness — تمرير آلي للنمطية،
   تصعيد للحالات الناقصة/المشتبه بها مع تلخيص الأدلة وسبب التصعيد.
6. **تدقيق مستمر**: التقاط الانحرافات وانتهاكات السياسات والشذوذ.
7. **ذكاء استثناءات**: تجميع وسبب جذري ومقترحات (غير نهائية قبل التحقق).
8. **ذاكرة**: أصل كل قرار مع سلامة سجل التدقيق (hash chain).
9. **محفز تطوّر**: تنبيه عند تجاوز مؤشرات العملية للعتبات.

## مبادئ ملزمة (من الوثيقة)

- **النتيجة قبل العملية** — لا تُقدَّس الخريطة الحالية لمجرد أنها قائمة.
- **الاستثناء جزء من التصميم** — صمّم للكشف عنه وتوجيهه وحلّه.
- **تغيّر ملكية العملية** — مالك واحد مسؤول عن النتيجة من البداية للنهاية.
- **فصل المعاملات عن المنطق** — العتبات تُعدَّل دون إعادة بناء العملية.
- **لا إفراط ولا نقص في التحكم** — عتبات واضحة، تصعيدات قابلة للتعديل،
  وسجل يشرح لماذا سُمح بالفعل أو مُنع.
- توصيات محركات الذكاء **ليست نهائية** قبل التحقق البشري.

## حدود هذه النسخة

هذه **نواة إثبات قدرات** (القسم 20.11): خريطة حية وتنبيهات، استقلالية
وتوجيه، ذاكرة وذكاء استثناءات — بمنطق قواعدي حتمي قابل للاختبار.
نقاط التوسع الطبيعية: استبدال مصنّفات القواعد بنماذج لغوية (LLM)،
واجهة Human Interface Runtime، ربط أنظمة فعلية (ERP/BPM)،
وسوق العمليات/الوكلاء — وكلها مؤجلة عمداً إلى ما بعد إثبات القيمة.
