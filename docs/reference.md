# ملاحظات التطابق مع الوثيقة المرجعية

هذا الملف يربط كل مكوّن برمجي بموضعه في وثيقة «إعادة تصميم سير العمل —
المرجع الشامل»، ويوثّق قرارات التنفيذ والتبسيط المتعمدة.

## خريطة التطابق

### الأطر المنهجية (القسم 4)

- **A.G.E.N.T (4.1)**: موزّع على الوحدات —
  A (التدقيق) ← `discovery.py`، G (التقييم) ← `analysis.py`،
  E (الهندسة) ← `redesign.py`، N (التوجيه) ← `runtime.py` + `attention.py`
  + `autonomy.py`، T (التتبع) ← `audit.py` + `trust.py` + مقاييس العرض.
- **TDF (4.5)**: `agents.py` — الأدوار الأربعة + Process Harness في
  `runtime.py`.
- **P.R.I.S.M (4.6)**: التقسيم المعياري (بنية الحزمة)، إعادة محاذاة
  المسؤوليات (`allocation.py`)، طبقات البيانات (`models.py`)، المحاكاة
  (`simulation.py`)، الحوكمة بالمقاييس (`evolution.py`).

### مبادئ التصميم التفصيلية (القسم 3.1)

| المبدأ | أين يظهر في الكود |
| --- | --- |
| فصل المنطق عن المعاملات | عتبات `AutonomyBoundaryEngine` و`ProcessEvolutionProtocol` معاملات ممرّرة لا ثوابت مدفونة |
| بناء معياري | كل محرك وحدة مستقلة بواجهة واحدة |
| تقليل الافتراضات الضمنية | `Policy.condition` صريحة وقابلة للتقييم؛ مبرر إلزامي لكل قرار تصميم |
| فصل القواعد عن الحكم | `StepNature` ومصفوفة `HumanAgentAllocator` |
| وحدة الأتمتة | `AutonomyBoundaryEngine.decide` لكل خطوة × حالة |
| التصميم القائم على الأدلة | `Evidence` في `ProcessState` وقرار `DecisionAgent` يقرأ الأدلة لا فروعاً مسبقة |
| اختبار «وماذا بعد؟» | شروط الحذف في `RedesignEngine.redesign` |
| حلقات التغذية الراجعة | `runtime.py` ← `exceptions.py` ← `memory.py` ← `evolution.py` |

### الحوكمة (القسم 7)

- المستويات الأربعة ← `AutonomyLevel` (مع `FORBIDDEN` كمخرج خامس).
- مسارات التصعيد الثمانية ← `escalation_policy` في `RedesignSpec`
  ومنطق `need_human` في `runtime.py`.
- محرك حدود الاستقلالية = ثقة + مخاطر + سياق + سياسات ←
  `AutonomyBoundaryEngine.decide`.
- شهادات الثقة والعقود والتفويض المحدود ← `TrustEngine` +
  `Policy` + `autonomy_bounds` لكل خطوة.
- السجلات غير القابلة للتلاعب ← سلسلة التجزئة في `ProcessMemory`.

### المحركات التفصيلية (القسم 9)

كل محرك من 9.1–9.9 و9.12 له وحدة مقابلة (انظر جدول README).
المحركات المؤجلة عمداً (20.x / 16.4 — أفكار توسّعية): Process Genome
الكامل، Agent Marketplace، Human-Agent Negotiation، Regulatory Change
Adapter — لأنها تتطلب بنية أساسية ناضجة وبيانات تاريخية ومعايير هوية.

## قرارات تبسيط متعمدة في نواة إثبات القدرات

1. **مصنّفات قواعدية** بدل نماذج لغوية في `exceptions.py` و`analysis.py`
   — حتمية وقابلة للاختبار؛ واجهة `classify` تسمح بالاستبدال لاحقاً.
2. **المحاكاة مونت كارلو خطية** (لا شبكات طوابير كاملة) — كافية لمقارنة
   السيناريوهات نسبياً، وهو الغرض المعلن في 9.2.
3. **السياسات تعبيرات بايثون** مقيّمة في بيئة مقيّدة (`__builtins__` فارغ)
   — Policy as Code بسيط؛ الإنتاج يتطلب DSL أو محرك سياسات مخصصاً.
4. **الذاكرة SQLite محلية** — تكفي لإثبات أصل القرار وسلامة السجل؛
   التوزيع والنسخ الاحتياطي قرار تشغيلي لاحق.
5. **الموافقة البشرية دالة ممرّرة** (`HumanApprovalFn`) — تفصل الحزام عن
   قناة التفاعل (CLI اليوم، واجهة غداً) دون تغيير المنطق.

## ما لا تدّعيه هذه النسخة

- لا تدّعي استقلالية فعلية على أنظمة إنتاج — كل التنفيذ داخل
  `ProcessHarness` مع موافقة بشرية إلزامية عند الفشل.
- لا تتحقق من الأرقام المرجعية الواردة في المواد المصدرية للوثيقة —
  الوثيقة نفسها تذكر أنها لم تُجرِ تحققاً مستقلاً.
